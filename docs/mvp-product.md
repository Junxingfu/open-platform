# 开放平台门户 MVP：产品评估与实现说明

> 版本：v0.1 MVP · 2026-10-24
> 范围：面向企业开发者的开放平台控制台（前端）+ 门户/开放 API（后端）

## 1. 需求理解

你描述的“银行开放平台”体验，本质是一个 **API 开发者门户（Developer Portal）**：

1. 企业拿到平台账号，登录控制台；
2. 浏览 API 目录，阅读接口文档、参数、示例、错误码；
3. 创建应用，获得 AppKey/AppSecret 等调用凭证；
4. 选择“应用 + API 产品”提交接入申请；
5. 平台运营审批、开通权限；
6. 企业按 OAuth2 或 HMAC 签名接入，开始调用；
7. 在控制台查看调用量、成功率、错误与密钥管理。

所以“一个前端服务 + 一个后端服务”是对的：

- **前端**：企业开发者/平台运营使用的 Web 控制台；
- **后端**：门户 API + 开放 API 运行时 + 授权/审计/防重放。

## 2. 用户与核心 Job

| 角色 | 核心诉求 | MVP 提供 |
|:---|:---|:---|
| 企业开发者（主） | 快速找到 API、看懂文档、拿到凭证、完成接入 | 登录、目录/详情、应用与密钥、产品申请、接入指南、调用统计 |
| 企业技术负责人 | 控制权限边界、管理多个应用 | 应用列表、产品开通情况、密钥轮换 |
| 平台运营 | 审核企业接入、控制开通范围 | 审批中心、全部申请、通过/驳回、开通产品 |
| 商务/合作经理（后续） | 合同、报价、SLA | 本期不做，预留产品维度 |

## 3. MVP 范围

### 3.1 已实现（In Scope）

- 门户登录（邮箱 + 密码，PBKDF2 哈希）、开发者/管理员两种角色；
- 概览：应用数、已开通产品、近 7 日调用、待处理申请、接入引导、公告、最近调用；
- API 目录：关键字/方法/产品筛选；
- API 详情：说明、认证方式、限流、请求头、参数、请求/响应示例、错误码、相关接口；
- 应用管理：创建应用、选择 OAuth2/HMAC、查看/复制/轮换密钥；
- 接入申请：选择应用 + API 产品 + 接入场景，提交申请；
- 审批中心：管理员查看全部申请，通过后自动创建订阅并授予 scope；
- 调用统计：总调用、成功率、平均耗时、按天趋势、按 API 排行、最近调用；
- 接入指南：OAuth2/HMAC 两种方式的步骤、代码示例、错误码；
- 开放 API 运行时：OAuth2 JWT、HMAC 签名、防重放、企业级授权、审计；
- 演示数据：2 个企业、2 个应用、2 个 API 产品、3 个 API、1 条待审批申请。

### 3.2 明确不做（Out of Scope）

- 企业自助注册、营业执照/KYC 审核、合同与电子签；
- 计费、套餐、发票、配额结算；
- 工单/评论/IM 协商（本期用“接入申请 + 审批意见”表达）；
- SSO/企业微信/钉钉登录、多因素认证；
- 生产级 MySQL/Redis、对象存储、消息通知；
- 真正的网关联调（`InternalCallClient` 仅保留客户端）；
- 在线“Try it”任意请求调试（涉及真实凭证与安全边界，放到下一阶段）；
- API 版本生命周期管理、灰度、下线公告；
- 多租户组织/成员/角色细粒度管理。

## 4. 关键产品决策

| 决策 | 理由 |
|:---|:---|
| 以 **API 产品** 为授权单元，而不是单 API | 企业接入时按产品签约，避免几十个 API 逐项授权；scope 定义在产品上，API 声明所需 scope |
| 接入申请必须审批，不自动开通 | 企业接入涉及合规/商务/安全评估；审批动作本身是风控和审计节点 |
| 门户 token 与开放 API token 完全隔离 | 防止控制台 token 被拿去调用业务 API，也防止业务 token 登录后台 |
| 密钥只在创建/轮换时完整展示一次 | 降低 secret 在页面/日志中长期暴露的风险；列表只展示掩码 |
| 文档先内置在代码中 | MVP 保证“文档与演示接口一致”；后续可迁移到文档平台/数据库 |
| 内存数据 + 演示账号 | 先验证产品闭环和交互，再替换持久化，避免过早做 CRUD 和数据库设计 |
| 前端独立 Vite 服务 | 前后端解耦，前端可独立部署/迭代；开发期用代理解决跨域 |

## 5. 成功指标（建议）

| 指标 | 目标 |
|:---|:---|
| 首次调用耗时（Time to First Call） | < 30 分钟 |
| 自助接入率 | > 70%（无需人工邮件/工单） |
| 审批 SLA | < 1 个工作日 |
| API 文档覆盖率 | 已上线 API 100% 有详情页 |
| 7 日激活率 | 创建应用的企业中 > 60% 完成首次调用 |
| 接入相关人工工单 | 相比现状下降 50% |

## 6. 技术方案

```text
┌──────────────────────────────┐        ┌────────────────────────────────────┐
│  frontend (Vite + React)     │        │  backend (Spring Boot 3.5 / JDK17) │
│  localhost:5173              │ ─────▶ │  localhost:8081                    │
│                              │ /portal│                                    │
│  登录 / 概览 / 目录 / 详情    │  /api  │  PortalAuthFilter                  │
│  应用 / 申请 / 审批 / 统计    │        │  PortalController                  │
│  接入指南                    │        │  PortalService / PortalStore       │
└──────────────────────────────┘        │                                    │
                                        │  /open/**  OAuth2 / HMAC 运行时      │
                                        │  AuditFilter → UsageTracker        │
                                        └────────────────────────────────────┘
```

- 前端：React 18 + React Router + Vite + TypeScript + 手写设计系统（无重型 UI 库）；
- 后端：Spring Boot 3.5.7 + Spring MVC + Nimbus JOSE + Caffeine/Redis starter；
- 门户认证：独立 RSA 密钥 + `iss=open-platform-portal` + `aud=portal-console` + 8 小时 TTL；
- 密码：PBKDF2WithHmacSHA256，用户独立随机盐；
- 门户 API：`/portal/api/**`，除登录外全部需要 Bearer token；
- 开放 API：`/open/**`，OAuth2 或 HMAC 签名，原有链路保持不变；
- 持久化：MVP 内存；接口已按“可替换实现”拆分（`AppRegistry` / `MutableAppRegistry` / `PortalStore`）。

## 7. 演示闭环（5 分钟）

1. 用 `dev@demo.com / Demo@1234` 登录；
2. 概览看到 2 个应用、1 个已开通产品、1 条待审批申请；
3. 进入“API 目录”，打开“企业风险核验”详情；
4. 在“我的应用”创建一个新应用（OAuth2），保存 AppSecret；
5. 对该应用提交 `enterprise-risk` 产品申请；
6. 退出，用 `admin@demo.com / Admin@1234` 登录，在“审批中心”通过申请；
7. 回到开发者账号，用新应用换 token，调用 `/open/v1/enterprise/risk-check`；
8. “调用统计”出现刚才的调用记录。

自动化测试已覆盖同样的闭环：`PortalFlowTest`。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|:---|:---|:---|
| 密钥泄露 | 高 | 一次性展示、掩码、轮换、日志脱敏；生产加二次认证与审计 |
| 审批成为瓶颈 | 中 | 审批 SLA、待办提醒、批量审批（下一阶段） |
| 文档与实现漂移 | 高 | 文档内置代码 + 测试校验关键字段；后续接文档平台 |
| 内存数据重启丢失 | 中 | MVP 可接受；生产换 MySQL/Redis |
| 多企业数据隔离 | 高 | 所有门户查询按 `enterpriseId` 过滤；管理员显式全量；生产加行级权限 |
| 令牌/密码安全 | 高 | 独立密钥/受众、PBKDF2、短 TTL、登录限流（下一阶段） |
| 无真实网关 | 中 | 先以演示 API 验证产品闭环；接入网关时补内部 Token Filter |

## 9. 下一阶段路线

### M1（当前 MVP）

门户闭环 + 演示 API + 自动化测试。

### M2（可试点）

- MySQL/MyBatis 替换内存；
- Redis 替换防重放/用量聚合；
- 企业注册/KYC、成员管理、SSO；
- 接入真实网关与内部 Token Filter；
- 工单/评论/审批通知；
- 在线调试（沙箱凭证 + 代理调用）。

### M3（规模化）

- API 版本生命周期、灰度/下线；
- 配额、计费、账单；
- 开发者社区、SDK 生成；
- 安全合规（等保、密评、审计留痕、数据分级）。
